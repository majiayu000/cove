# Cove 单服务器企业部署

2026-10-05，用户明确扩展原 R099 范围，并选择单台服务器、多租户登录、权限和预算隔离。

## 交付边界

增加可选企业启动模式，默认个人桌面模式保持原有入口。企业服务仍监听配置中的 loopback 地址，由运维配置的 HTTPS 反向代理公开。开发验收允许精确的 loopback HTTP origin。不会自动开放端口、部署公网、创建支付账号或改变日常 Cove 数据。

最小实现是一个登录入口和多个独立 Cove 实例：中央目录保存用户、密码摘要、租户和成员关系；每个租户使用独立数据库、凭据目录、请求记录、路由、资源归属、Key 和预算账本。复用现有 instance 预算作为整个租户预算，原 Key/路由预算继续叠加。不建立新的计费引擎。

平台管理员管理租户、用户和成员；租户管理员管理本租户的模型来源、Key、路由和预算；查看者只能读取本租户用量、请求和预算。密码使用独立随机盐的 Argon2id；登录使用有限生命周期、不落盘的 HttpOnly/SameSite 会话。成员移除、用户停用和租户停用对下一次请求立即生效。跨租户 Key、资源、游标和管理凭据不能互用。

远程用户不能调用桌面客户端文件写入、主机服务安装、更新、恢复、诊断导出、配置导入导出或遥测配置接口。OAuth 的本机浏览器回调流程没有远程授权合同，因此企业模式拒绝启动它；显式 API 凭据和已验证的原生协议能力继续走既有合同。企业模式不借用个人桌面的自动管理登录或主机凭据。

## 接口

- `POST /enterprise/session` 用户名和密码登录；`GET` 读取当前身份；`DELETE` 退出。
- `GET/POST /enterprise/tenants`；`PATCH /enterprise/tenants/{id}` 按版本修改名称、启停。
- `GET/POST /enterprise/users`；`PATCH /enterprise/users/{id}` 按版本启停；`POST /enterprise/password` 自行修改密码。
- `GET/PUT/DELETE /enterprise/tenants/{id}/members/{user_id}` 管理成员角色，修改携带版本。
- `GET /enterprise/audit` 平台管理操作的脱敏审计。
- `/t/{tenant_id}/admin/...` 认证与角色检查后进入该租户管理接口；`/t/{tenant_id}/v1/...` 和 `v1beta` 使用该租户 Key 认证。
- 页面根地址提供企业登录和租户选择，租户地址提供管理界面或只读报表。生成接入示例使用实际外部地址及租户前缀。

CLI 提供企业管理员的本机引导命令，密码从标准输入读取，不经命令行参数、配置文件或日志。必须使用独立的企业 data_dir；不得把日常个人数据目录直接当作企业目录。

## 验证与完成口径

真实 HTTP 测试覆盖匿名管理拒绝、错误密码、登录限流、角色越权、两租户目录隔离、相同模型的跨租户 Key 拒绝、成员撤销、会话退出、租户停用、版本冲突、密码摘要与审计脱敏、重启后目录和预算保留。浏览器覆盖登录、创建租户/用户、角色选择和只读报表。

性能门槛继续遵循主 Spec：8 路流 1800 秒，取消释放少于 5 秒，百万记录常用查询 P95 少于 300ms，额外首字延迟 P95 少于 20ms。短时基线不替代最终门禁。远程 HTTPS 部署、企业供应商资格、跨平台实机和正式账单对账分别需要相应环境与真实证据。
