## 1. CLIProxyAPI 与官方 Management Center

**身份与可比边界。** 官网 [Web UI 文档](https://help.router-for.me/management/webui) 明确将 `router-for-me/Cli-Proxy-API-Management-Center` 指为官方管理 UI，因此只计一个产品。主服务是 Go；UI 是 React/TS 单文件构建，服务在 API 端口提供 `/management.html`。这最接近 Cove 的“一个服务 + 浏览器管理页”，但该 UI 也可单独托管后连接另一后端，不能假设它只在本机。产品提供 OpenAI/Claude/Gemini/Codex 兼容 API；这里不验证每种上游模型的实际可用性。[官方仓库](https://github.com/router-for-me/CLIProxyAPI)；[Cli-Proxy-API-Management-Center README.md:20–132](https://github.com/router-for-me/Cli-Proxy-API-Management-Center/blob/4530da271ba2e89810d4dccebc57f3091afa590a/README.md#L20-L132)。

**第一次访问。** 先在服务配置设置管理 secret，再访问 `http://localhost:8317/management.html`，输入服务地址与 management key 连接。不是 username/password 账户系统，也不是操作系统 SSO。即使 localhost，管理请求仍要求 key；空 key 配置会禁用管理 API。当前 HEAD 已切换 v8 配置，字段为 `management.secret-key`，而在线 [Basic Configuration](https://help.router-for.me/configuration/basic) 仍展示旧 `remote-management.secret-key`；报告不把旧文档字段当 HEAD 唯一真相。[CLIProxyAPI config.example.yaml:59–90](https://github.com/router-for-me/CLIProxyAPI/blob/a270e7b9e57aaecd8f82555f44c2108518ad2330/config.example.yaml#L59-L90)

**日常登录、重启、初始凭据和恢复。** 用户自行设置持久管理 secret；源码启动时将明文散列并写回配置。UI 登录实质是带 key 拉取 config 校验，之后每个管理请求继续带 Bearer key。勾选 remember password 才把管理 key 写入 localStorage；恢复时再次发请求验证。服务重启本身不会作废该固定 secret；浏览器是否自动重连取决于 remember 与存储仍在。没有记住时刷新/重开页面须重新输入。这里是源码推导，没有实际重启测试。[CLIProxyAPI internal/config/config_load.go:114–132](https://github.com/router-for-me/CLIProxyAPI/blob/a270e7b9e57aaecd8f82555f44c2108518ad2330/internal/config/config_load.go#L114-L132) [Cli-Proxy-API-Management-Center src/stores/useAuthStore.ts:44–129](https://github.com/router-for-me/Cli-Proxy-API-Management-Center/blob/4530da271ba2e89810d4dccebc57f3091afa590a/src/stores/useAuthStore.ts#L44-L129) [Cli-Proxy-API-Management-Center src/stores/useAuthStore.ts:198–218](https://github.com/router-for-me/Cli-Proxy-API-Management-Center/blob/4530da271ba2e89810d4dccebc57f3091afa590a/src/stores/useAuthStore.ts#L198-L218) [CLIProxyAPI internal/api/handlers/management/handler.go:267–297](https://github.com/router-for-me/CLIProxyAPI/blob/a270e7b9e57aaecd8f82555f44c2108518ad2330/internal/api/handlers/management/handler.go#L267-L297)

忘记管理 key：本次未发现专门的官方“找回密码”页面或 CLI reset 命令。由于配置存 bcrypt，不能从配置恢复原明文；以主机配置权限重新设置 `management.secret-key` / 启动环境管理 secret 后重启是**由配置装载逻辑推导的恢复路径**，不是已实测官方向导。UI 的“清理本地登录数据”只清浏览器凭据，不能等同服务器密码重置。[CLIProxyAPI internal/config/config_load.go:114–132](https://github.com/router-for-me/CLIProxyAPI/blob/a270e7b9e57aaecd8f82555f44c2108518ad2330/internal/config/config_load.go#L114-L132) [CLIProxyAPI internal/api/handlers/management/handler.go:367–397](https://github.com/router-for-me/CLIProxyAPI/blob/a270e7b9e57aaecd8f82555f44c2108518ad2330/internal/api/handlers/management/handler.go#L367-L397)

**三类身份。** 管理 secret 控制管理 API；下游 `access.api-keys` 用于客户端调用；上游 `api-keys.*` 或 OAuth 凭据文件由网关访问供应商。v8 中根 `api-keys` 已用于上游分组，不能与下游列表混淆。OAuth 页面中 Codex/Claude/Antigravity 等授权是**上游账户授权**，不是登录管理后台；token 放 `oauth.auth-dir`。[CLIProxyAPI config.example.yaml:59–90](https://github.com/router-for-me/CLIProxyAPI/blob/a270e7b9e57aaecd8f82555f44c2108518ad2330/config.example.yaml#L59-L90) [CLIProxyAPI config.example.yaml:690–708](https://github.com/router-for-me/CLIProxyAPI/blob/a270e7b9e57aaecd8f82555f44c2108518ad2330/config.example.yaml#L690-L708) [Cli-Proxy-API-Management-Center README.md:20–132](https://github.com/router-for-me/Cli-Proxy-API-Management-Center/blob/4530da271ba2e89810d4dccebc57f3091afa590a/README.md#L20-L132)

**模型和 Key 入口。** 实际页面名 `Config Panel` 管下游 proxy API keys；`AI Providers` 填上游 Key/Base URL/模型别名，OpenAI compatible 可从 `/v1/models` 导入模型；`Auth Files` 上传凭据、查看凭据支持模型；`OAuth` 启动授权；`System` 获取网关 `/v1/models`，要求至少一个下游 key。OpenAI provider 的 `chat/completions` 测试在浏览器执行，会受 CORS/浏览器网络影响；这不能替代网关进程连通性验证。[Cli-Proxy-API-Management-Center README.md:20–132](https://github.com/router-for-me/Cli-Proxy-API-Management-Center/blob/4530da271ba2e89810d4dccebc57f3091afa590a/README.md#L20-L132)

**开源与付费边界。** 主服务 MIT；官方 UI MIT。上述管理登录、模型发现、上游 OAuth、下游 Key 页面均在开源仓库，没有证据显示需付费解锁。赞助商的付费 API 不等于软件许可证或官方托管套餐；本次没有核验独立商业/托管版本。[CLIProxyAPI LICENSE:1–21](https://github.com/router-for-me/CLIProxyAPI/blob/a270e7b9e57aaecd8f82555f44c2108518ad2330/LICENSE#L1-L21) [UI 官方仓库](https://github.com/router-for-me/Cli-Proxy-API-Management-Center)

**对 Cove 的启示（建议）。** 服务启动后让用户可以直接打开固定 URL，以一个持久的个人管理凭据进入；明确显示“管理密码/密钥”和“客户端 API Key”的不同用途。可借鉴重连/记住选项，但不照搬把管理 secret 可逆混淆后放 localStorage 的实现，也不需要复制远程多后端、插件、全部模型别名治理。没有证据支持“个人 Go 网关必须只接受一次性启动票据”。

## 2. CC Switch

**身份与可比边界。** 官方 [release 渠道声明](https://github.com/farion1231/cc-switch/releases) 指定 `ccswitch.io`、`farion1231/cc-switch`、GitHub Releases 为官方；排除搜索中 `cc-switch.cc` 和其他 fork。它是跨平台 Tauri 桌面管理器，主要替客户端改供应商配置，另可启用 Rust 本地路由；不是可直接部署给浏览器访问的管理站。Tauri 启动链直接渲染 App；“依赖本机用户有权打开应用/读数据”是信任边界描述，不表示应用每次做 OS 密码/Keychain 登录。[cc-switch src/main.tsx:88–130](https://github.com/farion1231/cc-switch/blob/a1216b7e359466be98f3c783cc290e7040de26d4/src/main.tsx#L88-L130) [官方仓库](https://github.com/farion1231/cc-switch)

**第一次访问、日常与重启。** 安装后打开应用，点 `+` /“添加新供应商”选择预设并填写 API Key，直接管理配置。本次审阅的启动路径没有管理密码表单，因此初始管理员密码、管理会话续期和管理密码恢复均**不适用**。重开应用从本地数据库/设置加载；上游 OAuth token 是否过期另论，不能把上游登录恢复当管理会话续期。[cc-switch docs/user-manual/zh/2-providers/2.1-add.md:1–21](https://github.com/farion1231/cc-switch/blob/a1216b7e359466be98f3c783cc290e7040de26d4/docs/user-manual/zh/2-providers/2.1-add.md#L1-L21) [cc-switch src/main.tsx:88–130](https://github.com/farion1231/cc-switch/blob/a1216b7e359466be98f3c783cc290e7040de26d4/src/main.tsx#L88-L130) [cc-switch README_ZH.md:470–486](https://github.com/farion1231/cc-switch/blob/a1216b7e359466be98f3c783cc290e7040de26d4/README_ZH.md#L470-L486)
