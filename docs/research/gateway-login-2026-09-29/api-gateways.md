# Cove 登录设计调研：LiteLLM、Bifrost、Portkey Gateway

核验日 2026-09-29。方法为官方联网文档 + 固定 main 源码阅读。没有启动项目、建立管理员、登录供应商、发送模型请求；下述「重启保留/恢复」是代码推导，不冒充实测。上游订阅 OAuth 与管理登录 OAuth 分开。

## LiteLLM

- **定位/部署**：开源 Python SDK + HTTP AI Gateway，Admin UI 属自托管 Proxy 本身；官方 quickstart 为网关 + PostgreSQL，模型、下游密钥、日志存 DB。Hosted Proxy、Enterprise 为独立选项，Cove 不需要组织、SSO/RBAC。[L6](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/docker/docker-compose.quickstart.yml#L1-L41) [LD1](https://docs.litellm.ai/docs/proxy/docker_quick_start)
- **首次访问**：operator 先设置 master key 和 salt key，启动后访问 `http://localhost:4000/ui`；用户名默认 `admin`，密码默认 `LITELLM_MASTER_KEY`，`UI_USERNAME`/`UI_PASSWORD` 可覆盖。不是匿名抢注首个管理员，也不是首次网页向导自设密码。匹配 operator 凭据直接取得 PROXY_ADMIN；默认 UI 登录要求 DB。[L1](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/litellm/proxy/auth/login_utils.py#L121-L145) [L2](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/litellm/proxy/auth/login_utils.py#L317-L360)
- **日常与重启**：UI 登录签发 DB session key 和有 exp 的 JWT；默认24小时。cookie 由 JS 读取后组装 API Authorization，因此非 HttpOnly。只要 DB/master key保留且未过期，单纯服务重启不应强制失效（源码推导）；浏览器 session cookie是否恢复也取决于浏览器。不能宣称「永久免登录」。[L3](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/litellm/proxy/auth/login_utils.py#L478-L498) [L4](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/litellm/constants.py#L1745-L1745) [L5](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/litellm/proxy/management_endpoints/ui_sso.py#L2812-L2827)
- **恢复**：operator 可在运行配置重设 UI_PASSWORD 后重启；忘记 UI 密码不等于丢失上游 API key。master key还能管理API；salt key丢失/替换会令已加密上游凭据无法解密，必须单独保留。官方没有本次核实的个人GUI“忘记密码”闭环。[L1](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/litellm/proxy/auth/login_utils.py#L121-L145) [L10](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/litellm/proxy/auth/login_utils.py#L245-L253) [L6](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/docker/docker-compose.quickstart.yml#L1-L41)
- **三种凭据**：master key 是网关 root/API admin且默认兼作 UI 密码；provider API keys/OAuth tokens是上游；virtual keys 是下游客户端调用凭据。UI登录内部也生成专用受期限约束 key，因此UI session实现与API key系统有关，但不应把用户分发key当管理员密码。[L2](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/litellm/proxy/auth/login_utils.py#L317-L360) [LD4](https://docs.litellm.ai/docs/proxy/virtual_keys)
- **模型/Key**：Models + Endpoints → Add Model，选择provider和目录模型、填provider credential、Test Connect、Add Model；Playground做请求测试；Virtual Keys → + Create New Key 或 POST `/key/generate`。目录存在不等于凭据真实可调用，Test Connect才是独立验证。[L8](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/ui/litellm-dashboard/src/components/add_model/AddModelForm.tsx#L420-L449) [L9](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/ui/litellm-dashboard/src/components/organisms/create_key_button.tsx#L644-L662) [LD1](https://docs.litellm.ai/docs/proxy/docker_quick_start) [LD2](https://docs.litellm.ai/docs/proxy/client_setup/overview)
- **协议/订阅**：OpenAI Chat Completions/Responses、Anthropic Messages、Gemini generateContent有源码入口。特别注意当前官方有 `chatgpt/` provider：ChatGPT订阅device-code OAuth、持久化auth.json、refresh token，支持Responses及桥接Chat Completions；不只是API Key网关。此授权独立于管理员登录。[L11](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/litellm/proxy/response_api_endpoints/endpoints.py#L194-L220) [L12](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/litellm/proxy/anthropic_endpoints/endpoints.py#L120-L133) [L13](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/litellm/proxy/google_endpoints/endpoints.py#L17-L30) [L7](https://github.com/BerriAI/litellm/blob/684a1edd44efa3a7c7f0395ccfa1bf9803017ea2/litellm/llms/chatgpt/authenticator.py#L43-L76) [LD3](https://docs.litellm.ai/docs/providers/chatgpt)
- **Cove取舍（判断）**：借鉴“管理凭据/上游连接/下游Key”名称分离、添加模型后测试、可复制客户端配置。不要搬Postgres+组织权限、也不必照搬master key兼任UI密码或非HttpOnly cookie。证据表明它选择密码是中心化服务器部署选择，不能证明个人macOS必需账号体系。

## Bifrost

- **定位/部署**：开源 Go SDK + Go HTTP网关，NPX分发二进制或Docker，自带Web管理；默认localhost:8080、SQLite config/log DB，macOS默认数据目录 ~/.config/bifrost。Enterprise另有OIDC、RBAC、集群等能力，不混入个人默认体验。[BD1](https://docs.getbifrost.ai/quickstart/gateway/setting-up)
- **首次访问**：默认不启用管理认证，直接进入管理UI，并非admin/admin。可到 Workspace → Config → Security → Password protect the dashboard，自设用户名/密码保存即时生效，或operator通过配置预置身份。未启用auth的访问在中间件中标记local admin。[B1](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/transports/bifrost-http/handlers/middlewares.go#L1191-L1216) [B4](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/docs/quickstart/gateway/setting-up-auth.mdx#L19-L51)
- **首次所有权细节**：当前代码只有第一次创建管理员（auth_config尚不存在且要启用）要求提前在config/env设置的setup_token。无token或不匹配拒绝创建；一旦有管理员便不再靠setup_token。官方标注从2.0.0-prerelease3起要求，不能回溯称所有稳定旧版已有。这个token不保护全部初始管理读取/写入，未设auth时常规API仍放行。[B2](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/transports/bifrost-http/handlers/config.go#L897-L930) [B3](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/transports/bifrost-http/handlers/middlewares.go#L1010-L1029) [B4](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/docs/quickstart/gateway/setting-up-auth.mdx#L19-L51) [B1](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/transports/bifrost-http/handlers/middlewares.go#L1191-L1216)
- **日常与重启**：启用后用户名密码登录。当前源码使用数据库存30天session + HttpOnly SameSite=Lax cookie，logout删session，改认证配置清空sessions。持久化DB保留时普通重启可保留有效登录（代码推导）。官方网页尚称localStorage存Bearer token，**与本次SHA源码不一致，以源码报告实际实现**。[B5](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/transports/bifrost-http/handlers/session.go#L117-L168) [B6](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/framework/configstore/rdb.go#L6965-L6988) [B7](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/transports/bifrost-http/handlers/config.go#L987-L995) [BD2](https://docs.getbifrost.ai/quickstart/gateway/setting-up-auth)
- **恢复**：源码存在启动时从文件/secret reference加载管理员凭据、比对DB、密码变化则hash并更新DB且清空sessions，可供operator有本机配置权限时恢复（代码推导，未运行验证配置协调的全部条件）；本次未找到明确“忘记密码”GUI流程。不要声称setup_token是已有账号重置万能钥匙。[B8](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/transports/bifrost-http/lib/config.go#L4667-L4738) [B3](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/transports/bifrost-http/handlers/middlewares.go#L1010-L1029)
- **三种凭据**：管理username/password/session；Model Providers中的供应商API keys；Virtual Keys中的sk-bf-*下游访问令牌。管理auth开关还可影响推理认证，但virtual keys单独施加模型/供应商/额度限制，普通下游VK不能据此推导为管理员。[BD2](https://docs.getbifrost.ai/quickstart/gateway/setting-up-auth) [BD3](https://docs.getbifrost.ai/features/governance/virtual-keys) [BD4](https://docs.getbifrost.ai/quickstart/gateway/provider-configuration)
- **模型/Key**：Model Providers → provider → Add Key；key可限制models。源码有Refresh model list及逐key刷新，可区分模型发现和请求验证。官方quickstart用curl完成首次推理；本次未证明存在通用一键连通性测试按钮，不写成已有。Virtual Keys → Add Virtual Key → Create Virtual Key。[B9](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/ui/app/workspace/providers/views/modelProviderKeysTableView.tsx#L120-L147) [B10](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/ui/app/workspace/virtual-keys/views/virtualKeysTable.tsx#L928-L945) [BD1](https://docs.getbifrost.ai/quickstart/gateway/setting-up) [BD3](https://docs.getbifrost.ai/features/governance/virtual-keys) [BD4](https://docs.getbifrost.ai/quickstart/gateway/provider-configuration)
- **协议/订阅**：OpenAI Chat/Responses、Anthropic Messages、Gemini协议转换已证实。上游API Key和云身份凭据都有；当前GitHub Copilot provider是GitHub App server-to-server token。未查到内置ChatGPT/Claude个人订阅浏览器OAuth授权流程；不将MCP OAuth或企业SSO计作此能力。[B11](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/transports/bifrost-http/integrations/openai.go#L700-L713) [B12](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/transports/bifrost-http/integrations/anthropic.go#L119-L129) [B13](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/transports/bifrost-http/integrations/genai.go#L1408-L1439) [B14](https://github.com/maximhq/bifrost/blob/bf515003df2acc8a836d5825d0a62a79ce3b2c82/core/providers/githubcopilot/githubcopilot.go#L1-L18)
- **Cove取舍（判断）**：它证明确有成熟产品默认不设管理密码。可借鉴本地立即使用、可选保护、长会话和三类凭据分离。但不要照搬“未auth即local admin”去处理Cove已有上游凭据的远程可达Web API；setup_token仅能防抢先建账号，不能替代已有数据管理边界。应先明确Cove原生进程/本机所有权证明，再决定需不需要额外密码。

## Portkey Gateway（限定开源main快照）

- **定位/部署**：TypeScript/Hono轻量Gateway，Node npx/Docker及其他runtime；开源仓库的本地Console与app.portkey.ai托管控制台是两件事。README已提示2.0预发布分支；本次只检查main，不能把未来企业控制平面合并承诺当已装能力。[PD1](https://github.com/Portkey-AI/gateway) [PD4](https://portkey.ai/docs/product/product-feature-comparison)
- **首次访问**：本地开发的 `http://localhost:8787/public/` 当前源码要求预先设置conf.json.admin_token；缺该配置显示提示，存在则输入token解锁。没有用户名注册、默认账号密码或“首访设密码”。production/headless分支不提供该本地UI。官方公告写>1.16.0生效，但此main package.json仍为1.15.2，故只能保证本次源码状态，不能据此断言npm 1.15.2有该行为。[P1](https://github.com/Portkey-AI/gateway/blob/669825cbe89ee51569918b8f78a9db486fd69dd4/src/start-server.ts#L24-L65) [P2](https://github.com/Portkey-AI/gateway/blob/669825cbe89ee51569918b8f78a9db486fd69dd4/src/middlewares/adminAuth/index.ts#L4-L19) [P4](https://github.com/Portkey-AI/gateway/blob/669825cbe89ee51569918b8f78a9db486fd69dd4/src/middlewares/adminAuth/index.ts#L123-L160) [PD2](https://github.com/Portkey-AI/gateway/discussions/1656)
- **日常与重启/恢复**：凭token换12小时HttpOnly SameSite=Strict cookie，session存进程内Map；服务重启Map清空，需要重新输入admin_token。token在conf.json/构建输入中，拥有本机配置权限者可找回或更换并重启/重建；不是邮箱找回流程。日志stream要求会话或admin token。[P2](https://github.com/Portkey-AI/gateway/blob/669825cbe89ee51569918b8f78a9db486fd69dd4/src/middlewares/adminAuth/index.ts#L4-L19) [P3](https://github.com/Portkey-AI/gateway/blob/669825cbe89ee51569918b8f78a9db486fd69dd4/src/middlewares/adminAuth/index.ts#L52-L106) [P4](https://github.com/Portkey-AI/gateway/blob/669825cbe89ee51569918b8f78a9db486fd69dd4/src/middlewares/adminAuth/index.ts#L123-L160)
- **三种凭据**：本地admin_token只解锁Console/日志；上游provider API key随请求或routing config使用；本地UI没有已核实的“创建下游API key”管理页。源码可以从文件integrations构造virtual-key引用，不应据此称本地Console具有云端下游Key发行后台。云平台则另有Portkey API key与Model Catalog provider credentials。[P1](https://github.com/Portkey-AI/gateway/blob/669825cbe89ee51569918b8f78a9db486fd69dd4/src/start-server.ts#L24-L65) [P5](https://github.com/Portkey-AI/gateway/blob/669825cbe89ee51569918b8f78a9db486fd69dd4/src/public/index.html#L969-L1008) [P9](https://github.com/Portkey-AI/gateway/blob/669825cbe89ee51569918b8f78a9db486fd69dd4/initializeSettings.ts#L20-L68) [PD3](https://portkey.ai/docs/product/ai-gateway/virtual-keys)
- **模型/Key**：本地Gateway页“Let's make a test request”选择provider/API key→Test Request，提供routing config示例及Logs，足够验证单次接入；没有核实到本地持久化模型目录编辑/Key发行。/v1/models逻辑可转控制平面或provider代理。云平台旧Virtual Keys已迁入Model Catalog → Add Provider，不能抄旧截图描述为本地入口。[P5](https://github.com/Portkey-AI/gateway/blob/669825cbe89ee51569918b8f78a9db486fd69dd4/src/public/index.html#L969-L1008) [P8](https://github.com/Portkey-AI/gateway/blob/669825cbe89ee51569918b8f78a9db486fd69dd4/src/handlers/modelsHandler.ts#L15-L48) [PD3](https://portkey.ai/docs/product/ai-gateway/virtual-keys)
- **协议/订阅**：OpenAI Chat/Completions/Responses以及Anthropic Messages已由路由源码证实；上游API Key、Vertex服务账号OAuth等云凭据有实现。未找到本地用户ChatGPT/Claude订阅OAuth登录流程；服务账号OAuth不等于订阅账号授权。[P6](https://github.com/Portkey-AI/gateway/blob/669825cbe89ee51569918b8f78a9db486fd69dd4/src/index.ts#L133-L159) [P7](https://github.com/Portkey-AI/gateway/blob/669825cbe89ee51569918b8f78a9db486fd69dd4/src/index.ts#L233-L254) [P10](https://github.com/Portkey-AI/gateway/blob/669825cbe89ee51569918b8f78a9db486fd69dd4/src/providers/google-vertex-ai/utils.ts#L112-L140)
- **Cove取舍（判断）**：可借鉴token解锁无需另建账号、最小接入页→测试→日志。它不是完整本地连接管理产品；不能把云端组织/Model Catalog/API Keys/SSO复制为个人网关需求。12小时内存会话在重启失效也不适合作为Cove常驻macOS默认体验的直接模板。

## 对Cove的共识与未知

三者并无统一“个人网关必须账号密码”答案：LiteLLM是operator root密钥起步，Bifrost是默认无密码+可选管理员，Portkey当前本地界面是预设token解锁。共同可借鉴的是上游连接与下游客户端授权的边界、配置后可测试、重新打开后的明确会话行为。Cove选择密码前应单独决定首次所有权证明、已有凭据实例初始化、重启保留/锁定、恢复入口；不需要为此引入组织/SSO/RBAC。

完整固定SHA、文件行号、官方URL见原始研究目录中的 sources.json。所有结论为文档/源码核验；版本发布状态、浏览器真实跳转、失效与恢复路径未实测。
